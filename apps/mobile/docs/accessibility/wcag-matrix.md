Las asignaciones a rutas son una interpretación de evaluación del equipo. La matriz no afirma conformidad global ni AAA.

## Cómo registrar un resultado

Cada fila conserva ruta real, criterio y nivel, método Android, escenario, versión evaluada, resultado, evidencia y pendiente con tarea responsable. La versión B0 en una fila No probado identifica el código que se propone evaluar; no identifica una ejecución. Los códigos E de evidencia remiten al registro de versiones y dispositivos de este documento.

| Campo o estado | Uso                                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No probado     | Criterio aplicable o aplicabilidad por confirmar; falta una ejecución suficiente para emitir resultado. Puede tener evidencia parcial.                            |
| Fallido        | El escenario indicado tiene una barrera documentada en la versión de prueba. No se extrapola a otra versión.                                                      |
| Aprobado       | Reservado para una comprobación ejecutada con pasos, dispositivo, versión y evidencia suficiente para ese escenario. No acredita otros escenarios ni toda la app. |
| No aplicable   | Hay un motivo verificable en el inventario nativo actual. Revisar la decisión si se incorpora esa capacidad.                                                      |
| Histórica      | La evidencia pertenece a otra versión. Una captura antigua no se convierte en prueba de B0 por incluirla aquí.                                                    |
| Parcial        | Inspección visual, nodos, emisión de eventos o un recorrido limitado. No equivale a escuchar un anuncio ni a cubrir todos los controles.                          |
| Pendiente      | Acción concreta y tarea que comprobará o tratará el hallazgo. Un pendiente no es una prueba aprobada.                                                             |

Al ejecutar una fila, registrar fecha, commit completo del código servido, estado del árbol de trabajo, APK o cliente y versión, modelo/dispositivo, versión de Android y TalkBack, escala de fuente, orientación, configuración de prueba, pasos, esperado, observado y enlace a evidencia revisada. Si Metro sirve un diff local, registrar base y hash del archivo o diff además de la APK. Separar las acciones con gestos y confirmación auditiva de las acciones automáticas sobre nodos. Conservar el resultado anterior y añadir la nueva versión cuando se repita una comprobación.

Usar exclusivamente datos ficticios. Revisar que las capturas no incluyan notificaciones personales, diagnósticos, correos reales ni secretos. Los nombres de los fixtures de demostración no representan usuarios reales.

## Comprobaciones de esta entrega

TI4-46 verifica cobertura de archivos de ruta frente al inventario, existencia de enlaces locales, identificadores/niveles frente a la recomendación WCAG 2.2, versiones de los informes y separación de estados. No se ejecutaron TalkBack, mediciones de contraste o pruebas de pantalla en esta tarea. Los resultados de lint, formato, cspell y CI se adjuntan a la PR del commit documental. Las [capturas del recorrido documental](../evidence/ti4-46/README.md) muestran la matriz en GitHub y la apertura de una fuente de evidencia.
