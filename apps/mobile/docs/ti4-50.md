# Preferencias locales de accesibilidad

Issue: [TI4-50](https://linear.app/ceretime/issue/TI4-50/crear-almacenamiento-local-de-preferencias-de-texto-alto-contraste-y). Base final: `975e05648715eb17f56994d06e19b0a91dd392ad`. Implementación: `7f02788666546586f8328b79700edce7398e08d3`. La matriz de [TI4-46](accessibility/wcag-matrix.md) ya está integrada en esa base.

## Contrato y valores predeterminados

Application define `AccessibilityPreferences` y `AccessibilityPreferencesPort` sin importar React, Expo, almacenamiento nativo ni Convex. Cada instalación comienza con `textScale`, `highContrast` y `reduceMotion` en `system`. No son preferencias por cuenta ni por rol.

| Campo          | Valores admitidos         | Predeterminado |
| -------------- | ------------------------- | -------------- |
| `textScale`    | `system`, `1`, `1.5`, `2` | `system`       |
| `highContrast` | `system`, `on`, `off`     | `system`       |
| `reduceMotion` | `system`, `on`, `off`     | `system`       |

TI4-51 aplicará la precedencia entre estos valores y el sistema desde este mismo proveedor. TI4-50 entrega almacenamiento e hidratación; el centro de preferencias de TI4-58 consumirá este contrato para editar los valores.

## Almacenamiento y recuperación

El adaptador utiliza AsyncStorage `2.2.0`, versión recomendada por [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/async-storage/). Es almacenamiento local sin cifrado y contiene exclusivamente los tres ajustes. No guarda identidad, solicitudes, acompañamientos ni credenciales. La clave única es `ceretime.accessibility-preferences.v1` y el contenido es `{ version: 1, preferences: { textScale, highContrast, reduceMotion } }`.

La lectura distingue `stored`, `default` y `recovered`. Ausencia devuelve defaults. JSON corrupto, versión desconocida, campos incompletos o valores inválidos recuperan todos los defaults en memoria. Leer nunca sobrescribe el dispositivo. Un fallo de lectura entrega defaults y `read-failed`, permite reintentar y bloquea escrituras hasta poder leer los datos anteriores. Una versión desconocida solo se reemplaza cuando el usuario actualiza expresamente una preferencia.

Una instancia del adaptador en `mobile-dependencies.ts` comparte caché y lecturas simultáneas. Las escrituras se procesan en orden y cada actualización parcial parte del último valor confirmado. Una escritura fallida devuelve `write-failed` y conserva la caché anterior. La cola sigue admitiendo operaciones después del fallo. Los snapshots son inmutables y la escritura descarta campos ajenos al contrato.

## Consumidores y errores

`app/_layout.tsx` monta un único `AccessibilityPreferencesProvider` por encima de la sesión. Los cambios de rol y el cierre de sesión conservan las preferencias de la instalación. `useAccessibilityPreferences()` entrega `preferences`, `status`, `source`, `error`, `reloadPreferences()` y `updatePreferences(patch)`.

`status` distingue `loading`, `ready` y `saving`. Los hijos permanecen montados mientras se hidrata. `updatePreferences` devuelve `true` únicamente después de confirmar la escritura; durante carga o guardado rechaza otra actualización con `false`. Un error conserva los valores anteriores y expone un mensaje fijo en `error`, sin incluir la excepción nativa. El consumidor debe mostrar ese texto al usuario y ofrecer reintento. Las pruebas lo muestran como alerta; TI4-58 debe conservar ese comportamiento en su interfaz.

`reloadPreferences()` permite reintentar una lectura fallida. No hay suscripciones de sistema ni estilos efectivos en esta entrega. El proveedor ignora respuestas de un puerto anterior y respuestas recibidas después de desmontarse.

## Validación y evidencia de cierre

La suite `__tests__/accessibility-preferences.test.tsx` ejercita el contrato, datos ausentes y corruptos, versiones desconocidas, reinicio del adaptador, caché, escrituras simultáneas, errores, reintento, privacidad de mensajes, dos consumidores y limpieza. El almacenamiento nativo se sustituye por una memoria de prueba o por el mock oficial de AsyncStorage; el adaptador y el proveedor son los reales.

Comandos reproducibles desde la raíz:

```sh
bun run --cwd apps/mobile typecheck
bun run --cwd apps/mobile test --runTestsByPath __tests__/accessibility-preferences.test.tsx __tests__/navigation.test.tsx
bun run lint
bun run format:check
cd apps/mobile
bunx expo install --check
CI=1 bunx expo prebuild --platform android --no-install
cd android
JAVA_HOME=/tmp/ceretime-ti4-50-jdk17 ANDROID_HOME=/home/corvo/Android/Sdk ./gradlew assembleDebug -PreactNativeArchitectures=x86_64 --no-daemon --console=plain --max-workers=2
```

La dependencia requiere reconstruir el cliente Android existente para incluir AsyncStorage. Los archivos generados por prebuild y el APK quedan ignorados por Git.

Resultados del 5 de octubre de 2026: typecheck, lint, formato y CSpell aprobados. La suite completa aprobó 16 suites y 154 pruebas; la suite focalizada incluye 23 pruebas, incluida la conservación de preferencias al entrar y salir de los cuatro roles. CSpell se ejecutó con `npx --yes --package cspell --package @cspell/dict-es-es cspell lint --no-progress` porque Bun 1.4.0 rechazó el comando con dos opciones `--package` indicado por el proyecto.

`expo install --check` y prebuild Android aprobaron. El build `assembleDebug` para `x86_64` aprobó en 1 minuto y 22 segundos y generó `apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk`. Se utilizó Temurin JDK `17.0.20.1`, descargado del servicio oficial de Adoptium en una carpeta temporal. Java 26 del sistema carecía de compilador y JBR 25 falló en la configuración CMake de Worklets; ambos fueron intentos fallidos de herramientas locales, previos al build aprobado. El enlace nativo generado incluye `AsyncStoragePackage`.

La revisión de impacto verificó con código real que una escritura pendiente o fallida conserva el snapshot confirmado, que una respuesta de un puerto anterior no reemplaza el vigente y que la entrada/salida de los cuatro roles mantiene una única lectura y la preferencia guardada. El efecto de hidratación puede emitir avisos de `act` en las pruebas existentes del router profesional; esas pruebas aprobaron y no se silenciaron los avisos.

La [evidencia nativa](evidence/ti4-50/README.md) registra la ejecución autorizada con `ceretime-mobile` en Medium_Phone, Android 17, Expo SDK 57 y AsyncStorage real. Incluye valores predeterminados con clave ausente, guardado confirmado, lectura tras detener y reabrir el proceso, recuperación de JSON corrupto y nuevo guardado. El consumidor temporal de prueba se conserva como un parche inactivo para reproducir la validación; no queda una ruta de prueba en la aplicación.

La revisión posterior reprodujo un callback retenido que escribía en un puerto anterior después de reemplazar la dependencia del proveedor. La corrección vincula cada operación con su puerto y rechaza el callback obsoleto antes de guardar. La regresión se ejecutó primero en rojo y después en verde, comprobando también que el puerto vigente sigue admitiendo escrituras. Esta corrección del proveedor se verificó con Jest; las capturas nativas corresponden al commit de implementación indicado al inicio y no se repitieron para este cambio.

La PR entrega la implementación y la evidencia para revisión humana. La integración y el cierre de Linear siguen pendientes. No se cambió el estado ni se publicaron comentarios en Linear.
