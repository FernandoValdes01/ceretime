# Aplicación de preferencias de accesibilidad

TI4-51 extiende el proveedor implementado en [TI4-50](ti4-50.md); este documento registra la política que la presentación móvil usa para combinar preferencias locales y ajustes del sistema.

## Precedencia

| Preferencia             | `system`                                  | Valor explícito                                                                  |
| ----------------------- | ----------------------------------------- | -------------------------------------------------------------------------------- |
| Tamaño de texto         | Usa `fontScale` del dispositivo.          | `1`, `1.5` o `2` define el tamaño final de la aplicación.                        |
| Alto contraste          | Usa la señal disponible de la plataforma. | `on` activa la paleta medida y `off` conserva la paleta normal.                  |
| Reducción de movimiento | Sigue el ajuste del dispositivo.          | `on` desactiva animaciones y `off` permite el comportamiento habitual de la app. |

Un tamaño de texto explícito reemplaza la escala del sistema, no se multiplica por ella; los componentes reciben `textScaleMultiplier` para aplicar la razón entre el tamaño elegido y la escala nativa vigente, así React Native no agranda el texto dos veces.

Una preferencia local explícita prevalece sobre el valor del sistema; en `system`, la app usa el sistema como fuente de verdad.

## Lectura de ajustes del dispositivo

La presentación lee `fontScale` desde `useWindowDimensions`, consulta reducción de movimiento con `AccessibilityInfo.isReduceMotionEnabled()` y mantiene el valor actualizado con `reduceMotionChanged`.

En Android, el alto contraste del sistema usa `AccessibilityInfo.isHighTextContrastEnabled()`; en iOS usa `isDarkerSystemColorsEnabled()` como señal disponible de colores oscuros del sistema. La app vuelve a consultar estos valores al regresar a primer plano porque React Native 0.86 no expone un evento para esos cambios.

Si una consulta de movimiento o contraste falla, se conserva `false` como valor del sistema hasta una consulta posterior; las preferencias locales siguen disponibles.

Reanimated recibe el modo resuelto desde el proveedor raíz para cubrir animaciones existentes sin crear ajustes propios en cada vista. Los nuevos consumidores deben leer `effective.reduceMotion` y no consultar ni guardar otra preferencia.

## Cambios de esta etapa

El proveedor resuelve y publica `effective.textScale`, `effective.textScaleMultiplier`, `effective.highContrast`, `effective.reduceMotion` y `effective.reduceMotionMode`. Sus listeners se retiran al desmontar y descartan consultas atrasadas.

Las pruebas `accessibility-preferences-policy.test.tsx` cubren la precedencia, la escala relativa y el tamaño nativo inválido; `accessibility-preferences-runtime.test.tsx` cubre el cambio de movimiento durante ejecución, la precedencia local y la limpieza de listeners.
