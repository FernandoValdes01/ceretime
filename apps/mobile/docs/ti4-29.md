# TI4-29 — hooks de consumo del área estudiantil

## API

`src/presentation/hooks/useStudentArea.ts` expone `useStudentArea(reader)`.
El `reader` es una implementación inyectada de `StudentAreaReader`; el hook no
conoce mocks, transporte ni infraestructura.

La lectura devuelve un único `StudentAreaSnapshot` por instancia y expone:

- `status`, `snapshot`, `error` y `reload` para el snapshot.
- `identity` para la identidad requerida (`loading`, `success` o `error`; nunca
  `empty`).
- `requests` y `accompaniments`, cada uno con `status`, `data` y `error`.
  Una colección vacía tiene estado `empty` de forma independiente.

Los datos anteriores se ocultan al iniciar una carga, tanto por `reload()` como
al reemplazar el reader. Las resoluciones o rechazos de una carga anterior y
las cargas posteriores al desmontaje se ignoran. También se convierten en
estado `error` los lanzamientos síncronos del reader y los rechazos de su
Promise.

Cuando una pantalla necesita varios agregados, debe usar una sola instancia de
`useStudentArea` para evitar lecturas redundantes e instantáneas inconsistentes.
También existen `useStudentAreaSnapshot`, `useStudentIdentity`,
`useStudentRequests` y `useStudentAccompaniments` para consumidores aislados;
cada instancia aislada realiza su propia lectura. Mantener estable la identidad
del reader mientras no cambie la fuente evita recargas accidentales; cambiarla
es una sustitución explícita de fuente.

## Alcance

La implementación consume únicamente el contrato provisional de TI4-5 y los
datos ficticios/anónimos existentes. No implementa sesión, autenticación,
envío de solicitudes, roles definitivos ni una integración real con TI2.

## Verificación

El test montado usa `react-test-renderer` 19.2.3 sin agregarlo a los manifests
de Expo. En una preparación local limpia, desde la raíz del repositorio,
instala solamente el tooling ignorado dentro de `apps/mobile` (no ejecutes una
instalación en la raíz):

```sh
npm install --prefix apps/mobile/node_modules/ti4-29-test-tools --cache apps/mobile/node_modules/.npm-cache --package-lock=false --legacy-peer-deps --ignore-scripts react-test-renderer@19.2.3
```

Si esos enlaces todavía no existen, créalos desde la misma raíz después de la
instalación. Las rutas eliminadas son únicamente artefactos ignorados del
tooling de pruebas:

```sh
rm -rf apps/mobile/node_modules/ti4-29-test-tools/node_modules/react
ln -s ../../react apps/mobile/node_modules/ti4-29-test-tools/node_modules/react
rm -rf apps/mobile/node_modules/react-test-renderer
ln -s ti4-29-test-tools/node_modules/react-test-renderer apps/mobile/node_modules/react-test-renderer
```

El renderer debe quedar en
`apps/mobile/node_modules/ti4-29-test-tools/node_modules/react-test-renderer`,
con el enlace `apps/mobile/node_modules/react-test-renderer` apuntando allí y
React resolviendo la misma instalación de `apps/mobile/node_modules/react`.
Estos son artefactos locales ignorados; no forman parte del commit.

Desde `apps/mobile/`:

```sh
node_modules/.bin/tsc --noEmit

```

colecciones vacías independientes, rechazo → reload → éxito, throw síncrono,
recargas superpuestas, reemplazo de reader con resolución y rechazo obsoletos,
ocultación de datos de la fuente anterior, desmontaje y StrictMode. La
verificación local actual usa los artefactos instalados de este workspace; no
afirma una ejecución desde un checkout limpio.
